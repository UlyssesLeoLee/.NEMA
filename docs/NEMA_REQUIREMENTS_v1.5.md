# NEMA v1.5 · 要件定义（IPA 风格）

## 产品目的
面向多 Agent 共享信息：在保持可确定性解析、UTF-8 级无损压缩与版本隔离的前提下，让已理解协议的大模型直接生成更少输出 Token 的文本。支持普通行、二维续写、带自定义表头/无表头 Table、5W1H 与有身份的 Node–Edge 图。

## 功能要求
| ID | 需求 | 验收 |
|---|---|---|
| REQ-001 | 默认 Table 第一行内容判定，精确 `\\ ` 为表头 | 0 表头与 1 表头案例均正确 |
| REQ-002 | 无表头自动 Column1..N | 后续扩列可正确处理 |
| REQ-003 | 空格横向字段、N 个空格续写 X(N−1) | 纵向说明保持顺序 |
| REQ-004 | 显式 `?` 5W1H，What 优先，` .` 尾空字段 | 不推测缺失列 |
| REQ-005 | 显式 `>` Graph，独立 Edge ID，支持正反无向自环和多边 | 方向不随图布局改变 |
| REQ-006 | 字典 `Tab+$N` 与内联 `^N` | 原子不会拆词；支持字面 `\\^` |
| REQ-007 | 自适应无损 `.nemat` | UTF-8 比较相同；无收益原文回退 |
| REQ-008 | IDE1.0/IME1.0 共享 Rust Codec，IME 默认写入 | 双写避免、手动 IDE 接管 |
| REQ-009 | AI 训练 / 留出评测、Token 基准可复现 | 按同一解析器生成标签 |
| REQ-010 | 三语静态网站和独立 Token 性能页 | 离线运行、展示失败样本 |

## 非功能要求
编码与解码不能执行输入内容；禁止静默写入真实密码、API Key、访问令牌；输入限制 16 MiB（参考实现）、字典长度和压缩膨胀倍数需要上限；增量更新需 CAS/epoch，校验 SHA-256；完全避免对非 NEMA 源代码文本做改写；用户编辑原生 `.nema` 优先。Tokenizer 成本优化必须计入传输声明/词典/解释/纠错，且不能对未测试的 GPT、Claude、Gemini 宣称收费节省率。

## 验收里程碑
M1 原生语法 + 解析器；M2 `.nemat` 无损往返 + 安全校验；M3 IDE/IME 接口与仲裁；M4 真实 Windows TSF/VScode/Tauri 端到端；M5 三家目标模型独立训练/生成可靠性及实际计费 Token 评估。当前包落实 M1、M2 参考实现及 M3 文档，不宣称 M4/M5 完成。
