# NEMA v1.4 统一语法规范（正式候选）

状态：**RC / 可运行参考规范，不代表已对任何商业模型完成训练或计费验证**。本文件是唯一权威的当前语法；`archive/` 内的旧规范均已废止。规范日期：2026-11-06。

## 1. 目标与非目标

NEMA 是供 AI Agent 交换的**纵向不规则二维文本格式**：**ASCII 空格横向定位、LF 纵向承载意群**；使用三种领域模式，允许学习其编码的模型直接写压缩表示，前端可以确定性解码。原生 `.nema` 面向编辑和可读渲染，压缩 `.nemat` 面向传输。

NEMA **不是** Rust、TypeScript、Python、SQL、JSON、Diff 等原生格式的替代品。原代码由对应文件及其工具链维护；NEMA 只记录任务、引用、说明、依赖和元数据。NEMA 压缩并不等于加密，秘密凭证使用 SecretRef，不进入共享字典。

## 2. 字符与文件结束

- 行终止符为 LF U+000A；内部不允许完全空行，最后恰好两个完全空白物理行（最后一条有效行之后三个 LF）。
- 领域标识和共享字典声明行以**一个真实 Tab U+0009** 起始。**Tab 不再承担正文横向字段分隔功能**，正文内禁止 Tab。
- 正文**ASCII 空格 U+0020** 承担横向字段定位；连续几个行首空格承担纵向续写的 X 坐标。正文不使用 Tab 列分隔。
- 所有领域具有独立 `ID` 和大于零的十进制 `revision`；例如 `\tT1 1`。ID 首字母 ASCII 英文字母，后续 `[A-Za-z0-9_.-]`。领域头只能在行首 Tab 后被识别。
- 非字面符号 `⇥` 仅在文档展示中表示 Tab，不能作为实际文件内容。

## 3. 三模式：Table 为默认

| 领域头（前缀真实 Tab） | 模式 | 说明 |
| --- | --- | --- |
| `T1 1` | 默认 Table | 不加模式符号，支持自定义表头或自动 columnN |
| `?T2 1` | 5W1H | 固定列顺序：**What → Why → How → Who → When → Where** |
| `>G1 1` | Graph | 节点、独立 Edge、箭头方向和带正文的关系 |

所有领域均可直接相邻，不需要空行；解析时 Tab 起始的严格领域头优先。任何非首行数据内容不应具有真实 Tab。

## 4. 默认 Table（本版本新增的关键规则）

**只有默认 Table 的第一条正文以 `\ `（一个反斜杠 + 一个 ASCII 空格）开头时，才是表头。** 表头用一个空格分隔单词型列名。其他情况第一条正文就是第一条数据，不能错误吞掉。

有表头：

```text
⇥T1 1
\ Agent Status Note
Claude Ready CheckSession
   AccessGranted.
Codex Failed InvalidToken
```

无表头：

```text
⇥T1 1
Claude Ready CheckSession
Codex Failed InvalidToken
```

第二例自动命名 `column1`、`column2`、`column3`，若后续数据行或续行使用第 4 列，则自动扩展 `column4`。这与 JSON 对象自动键 `column1`～`columnN` 的逻辑等价，但列身份来自顺序。显式表头的列名是单个无空格标识符、不得重复；多词列名建议 PascalCase（例如 `LastUpdatedAt`）。

注意：**任意 `\^`、`\.`、`\\` 开头的合法正文都不是表头**；仅 `\ ` 有此意义。若真实字段需要从字面量“反斜杠 + 空格”起始，须将反斜杠编码为 `\\`。

## 5. 横纵坐标与记录边界

- 新的非缩进行 = 新的 Table/Graph 数据记录；Table 中它是下一行、Graph 中它是下一个 Node/Edge。
- 行首恰好 N 个 ASCII 空格（N ≥ 1） = **续写当前记录的 X(N−1) 列**，其后的文本是完整意群，不增加新的记录。`␠` 仅用于教学图示。
- 例如 `␠text` → X0，`␠␠text` → X1，`␠␠␠text` → X2；对 Table、Graph 和 5W1H 均成立。
- 普通正文的一串空格分列，**同一列内部不能直接写未标记的 ASCII 空格**；需要以 PascalCase、共享字典原子或纵向意群编码。
- 英文按 PascalCase/acronym 分词：`HTTPItIs` → `HTTP It Is`。混合标识符必须经过已确认的字典引用，例如 `Validate^0BeforeAccess`，不能猜测 `APIKey` 一定属于一个原子。
- 中日文含汉字、假名的意群可以连续书写，例如 `请检查APIKey是否有效`、`APIKeyを確認してください`；不是必须换行。
- 纵向续写应**仅在需要表达意群边界、跨列对齐或缩写碰撞时使用**；避免无意义换行增 Token。

### 5W1H 的显式尾部空字段

新记录若在最后一项后有` .`，表示其后尚未写出的列明确为 null/空值，例如：

```text
⇥?T1 1
修复登录流程 防止越权 Rust .
```

这里 What/Why/How 有值，Who/When/Where 明确为空。没有 ` .` 则未提供，不等同于显式空。需要字面句号作为最后字段时请写 `\.`。点号只在**行尾独立字段**并且前面恰好一个空格时承担控制含义。若以 ` .` 结尾但没有缺失列，解析器也必须保留 `tail_empty=true` 标记供验证。

## 6. Graph 与有内容的 Edge

Graph X0 = Node ID，或者 `A>X>B` / `A<X<B` / `A=X=B`，其中 X 是**Edge ID**：

| 表达式 | 起点/终点 | 关系属性 |
| --- | --- | --- |
| `A>X>B` | A → B | X 有独立身份、名称及说明 |
| `A<X<B` | B → A | 图形箭头不可因布局翻转 |
| `A=X=B` | A — B | 无向关联 |
| `A>X>A` | A ↻ A | 自环 |
| `A>X>B`、`A>Y>B` | 两条 A→B | 平行多重边 |

X1 = 节点名/关系类型，X2 = 说明，其后可扩展属性；首行 `   text` 将 X2 说明继续附着到上一 Node 或 Edge。Edge ID 必须在图作用域内唯一。默认把两个方向看作两条独立 Edge，不强制引入 `<>` 语法。Graph 可以包含反馈环，**只有明确标识为依赖 DAG 的关系需要无环验证**。

```text
⇥>G1 1
A LoginAPI ReceivesRequests
B TokenStore Redis
C AuditService Events
A>X>B Reads CheckSession
   OnCacheMissRetry
B<Z<C Notifies TokenExpired
A=U=C Shares AuthPolicy
```

X：A→B，Z：C→B，U：A—C。Graph 的布局坐标是渲染器计算结果，**不写入原始关系语义**。

## 7. 共享字典：Tab + $N

原生 `.nema` 文档第一行可以声明 `\t$N`，紧随其后的 N 行为**无 Tab 的不透明原子**，索引从 0 开始；例如：

```text
⇥$2
APIKey
HTTPStatus
⇥?T1 1
Validate^0BeforeAccess PreventLeak Rust .
```

`^0` 展开后保留 `APIKey` 原貌，**不可内部 PascalCase 断词**。字典值的作用域是当前文档；不能依赖“模型自己找”来解析不存在的索引。`\^` 表示字面 `^`，`\\` 表示字面反斜杠，`\.` 在需要时保护字面点号。字典项要通过用户确认 / LSP / 标识符词库确定，不能猜测现实的 API 密钥或明文密码。

## 8. 无损传输 `.nemat`

`.nemat` 是**另一个媒体类型**，只有在显式协商后解码，绝不将其误认成 `.nema` 直接编辑。采用 `\t$N` 作为压缩传输字典清单；新增词条由编解码器自动选择，不侵入源文本。`^N` 用于重复原子替换，`\N字符` 是 RLE（N≥4，必须在 Token 成本有收益时采用），`	数字` 是数字前缀组选择器，后面的缩短领域 ID 从已观察到的完整 ID 词根恢复。

压缩前后必须满足：**解码后 UTF-8 字节完全一致，包括原始空格、Tab、LF、转义、显式表头及意群边界**。前端无需调用模型即可解压。模型可接受 `.nemat`，但模型的生成准确率仍需单独测试。禁止 RLE 编码横向空格、纵向 LF 或控制 Tab。

不要求 `.nemat` 比 `.nema` 必然短：编码器比较完整传输文本（含词典与控制符）的目标 tokenizer 成本，无收益返回原生 `.nema`。转换结果必须携带 format / MIME，扩展名不得与实际格式不一致。

## 9. 兼容性与验证

v1.4 对 v1.3 是破坏性变更（默认 Table 表头），不能悄悄复用旧的自动表头逻辑。迁移器须区分旧文件第一数据行是否为表头，无法确认时提示确认。测试包含无表头首行、显式表头、`\^`、`\^`、`\.`、多空间纵向列、日英中意群、边方向、字符串压缩往返、异常字典索引、版本增量及训练集一致性。

更详细的工程 API 见 `NEMA_DETAILED_DESIGN_v1.4.md`；所含 Python 参考实现不是 IDE1.0/IME1.0 的现成 Rust 生产模块。
