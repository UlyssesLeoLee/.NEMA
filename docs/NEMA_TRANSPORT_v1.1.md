# NEMA v1.1 `.nemat` 可逆传输协议（实验）

**定位**：传输优化，不是作者直接编辑的主格式。输入原生 `.nema`，输出 `.nemat`；解码须恢复完全相同的 UTF-8 字节（包括原始 PascalCase、空格位置、Tab 头和换行）。原生源码或数据库原文不应强转 NEMA。

## 明确语法

| 类别 | 实际控制字符 | 例子 | 说明 |
|---|---|---|---|
| 字典头 | TAB + `$` + 数字 | `⇥$2` | 定义后续两行完整字典值。`⇥` 在这里仅表示真实 Tab |
| 值字典 | 下一行一个值 | `PreventLeak` | 仅完整单元格替换，不替换子串 |
| 引用 | `^` + 整数 | `^0` | 引用字典 0 号值；仅数据单元内有效 |
| 字面 ^ | `\^` | `\^0` | 保留文字 `^0` 而非引用 |
| 数字前缀组选取 | TAB + 整数 | `⇥0` | 激活在此前完整领域头引入的 0 号 ID 词根 |
| 缩写领域头 | TAB + 数字尾部 + 空格 + 版本 | `⇥002 1` | 与当前组词根结合恢复领域 ID |
| 未命中优化 | 原生 `.nema` | 不强加头部 | 在传输 envelope 中通过 MIME/元数据标明实际格式 |

示例（真实 Tab）:

```text
	$2
PreventLeak
AuthService
	TaskLogin001 1
BuildLoginFlow ^0 ValidateHTTP Codex Today ^1
	002 1
ReviewHTTPStatus ^0 ValidateHTTP Claude Tomorrow ^1
```

**不要将 `⇥$2` 写进源文件**；必须写真实 Tab。字典头必须出现在文件首行，字典不跨文档、会话或 Agent 保持隐式状态；每一份压缩 payload 都能独立解码。字典最多 64 条、输入最大 16 MiB（原型限制，可配置）。

## 自动提炼算法

1. 只从解析合法的完整**正文单元**中寻找出现至少两次的值；Table 表头、Graph X0、领域头、密钥/令牌、客户隐私或用户排除的值永不入自动字典。
2. 同时生成 native / 仅数字前缀 / 仅共享字典 / 两者联合的候选。字典用贪心成本下降搜索，不能只按词频判断收益。
3. 拥有目标模型 tokenizer 时将**完整传输文本**（包括字典清单、数字前缀行、控制符、换行）送入 tokenizer 计数；否则仅作 UTF-8 字节代理优化，并注明不是模型 Token。
4. 每个候选完整解码，逐字节比较哈希与长度并重新解析；选分数最低者，无收益直接返回 native。
5. 提交文件内容/导出包采用稳定快照和版本 CAS，拒绝覆盖 IME 正在组合的缓冲区。

当前 Python 编码器为参考实现 `codec/nemat.py`；实际 IDE1.0 / IME1.0 仍需要独立 Rust 重写与双端一致性验证。`\^` 的引用优先级、词典寿命、前缀 ID 和字面字符的解释在此固定。

## 反例

- 本文中普通原生 5W1H 字段 `$Token` **不等于** `TAB+$N` 字典头。
- 数字 `123` 是单元格文字，**不是** `TAB+123` 前缀切换。
- `A>X>B` 在 Graph X0 不参与值字典替换，以保持图表达式可解析。
- `APIHTTP` 不是一个可靠的两个缩写拼接，应改为两个意群；传输编码无法自动修正用户原始语义不明确的表达。
- 未压缩内容不得以 `.nemat` 扩展名暗示压缩。API 应显式携带 `format=nema/1.1` 或 `nemat/1.1`。
