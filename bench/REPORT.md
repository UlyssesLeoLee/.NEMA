# NEMA v1.1 — 最新中英日三语言 Token 实测报告

## 测试范围

- 本地真实运行的 SentencePiece BPE 和 Unigram（模型存放 `bench/neutral_*.model`）。严格保留 ASCII SPACE、Tab、LF，不做会丢失空格坐标的归一化；没有调用 GPT/Claude/Gemini 官方 tokenizer。
- 每种语言有 60 个领域，每个领域 6 个字段，包含重复任务词汇。紧凑 NEMA 与纵向拆分 NEMA 的**机器渲染结果严格一致**；位置式 YAML 从 NEMA 的确定性语义视图构造，每条记录包含领域 ID、版本和六个值，**无重复字段键**。
- `.nemat` 数值包含完整字典头、字典值、索引、数字前缀和转义，每次编码后全字节解码比对；选取本地 tokenizer 成本最低的候选，无收益回退原生 `.nema`。
- 场景并不是自然语言大规模随机样本；中日文 BPE 对字符字节回退较多，因此字节效果偏离实际商业模型是有可能的；Graph 的 YAML 以明确关系对象记录为基准，优势包含了格式结构差异。

## 主要 BPE 结果

| 场景 | 原生 NEMA | 纵向版 | 位置式 YAML | 优化 `.nemat` | 原生 vs YAML | `.nemat` vs 原生 |
|---|---:|---:|---:|---:|---:|---:|
| 英文 60 领域 | 3012 | 3182 | 3849 | 1953 | +21.75% | +35.16% |
| 中文 60 领域 | 5532 | 5712 | 6009 | 3647 | +7.94% | +34.07% |
| 日文 60 领域 | 7062 | 7382 | 7539 | 4088 | +6.33% | +42.11% |
| Graph 40 Node / 160 Edge | 6752 | — | 13631 | 3224 | +50.47% | +52.25% |
| Table 200 行 | 4899 | — | 7889 | 2105 | +37.90% | +57.03% |
| 高熵领域 60 个 | 6362 | — | 7330 | 6185 | +13.21% | **仅 +2.78%** |

正值节省率 = `(baseline_tokens − candidate_tokens) / baseline_tokens × 100%`。Graph 与 Table 的 YAML 对照为结构明确的紧凑 JSON 内嵌 YAML 记录（YAML 流式序列），而不是最低限度的自定义裸 TSV；不能将其优势归因于 NEMA 特有 tokenizer 性质。

## 空格分列对 Tab 分列

**仅比较正文分隔符**：使用相同单元格内容、相同领域头和行顺序（这一控制组不作为新版 `.nema` 解析输入）。英文 BPE 空格版 3012，Tab 版 3242，空格少 **7.09%**；中文空格 5532 / Tab 5532、日文空格 7062 / Tab 7062，在当前 BPE 模型下差值为 **0%**。这并不意味着任何模型都相同。

**仅比较纵向拆分开销**：英文 3012 vs 3182（紧凑少 **5.34%**），中文 5532 vs 5712（少 **3.15%**），日文 7062 vs 7382（少 **4.33%**）。这些差值可因文本内容、长度和 tokenizer 改变，不能写成固定节省率。

## 结论与未覆盖范围

1. 英文 PascalCase 与“仅必要时纵向换行”减少了本地分词开销；中日文直接横向书写通常比强制拆行更好。
2. **What-first** 使单列自然文本不需要 Who/Why/How 的空位；这属于形式与使用便利性优化。
3. **高重复度的字典/数字前缀**给 Graph 与 Table 带来较大压缩收益；高熵数据收益较小。极短片段几乎无字典收益，编码器应回退。
4. 这些统计是**离线编码长度**。真实 API end-to-end Token 优势还取决于提示词说明成本、输出、失败重试、Agent 训练与连接协议；不得把历史 69% 字节压缩率直接宣传为本版本 Token 节省率。

数据完整文件：`results.json`、`results.csv`、`examples/*.nema`、`examples/*.nemat`、`examples/*.positional.yaml`。重新运行 `python bench/reproduce.py` 即可生成同一数据。网站专属页 `website/token-benchmark.html` 直接展示这些实测数据，离线可用。
